# 风扇模式切换与曲线保留

OpenFi 管理插件 `2026.09.12-r2` 修复两处行为：

- 原页面在调高“最低稳定输出”时，会把低于下限的曲线点直接改成该值。设为 100% 时，四个输出点全部变成 100%；随后调低下限不会恢复原曲线。现在保留输入的控制点，参数冲突时显示校验提示，需明确调整后才能保存。
- 原服务应用配置时先停止再启动风扇进程，退出保护和 PWM 初始化都会请求全速。现在通过 HUP 通知运行中的进程，在下次采样开始时重新读取配置，保留 PWM 和当前输出，继续执行正常的升速、缓降逻辑。

手动输出和自动曲线分别存储。反复切换模式、手动输出设为 100%、编辑曲线后切换再切回，都应保留四个自动控制点。最低稳定输出是两种模式共用的下限；设置固定手动转速应使用“手动输出”。

风扇从停转状态起转时仍保留一秒全速助推，CPU 过热或温度读取失败时仍请求全速。模块复位配置仅在发生变化时应用，LED 和实体开关继续周期读取配置。

## 验证

- `tests/openfi6c/curve.cjs` 使用 Chromium、实际曲线和滑块模板，以及仓库 LuCI 的 CBI 依赖处理代码。覆盖模式往返、手动 100%、未保存曲线、保存后重建页面、下限冲突。旧版可复现四点被改成 100%，修复版保留原值。
- `tests/openfi6c/form.lua` 使用实际 CBI 解析函数，验证模式往返保存独立参数，拒绝冲突下限而不覆盖曲线。
- `tests/openfi6c/reload.py` 在模拟 sysfs/UCI 环境运行实际风扇进程，发送 HUP 切换手动与自动，检查进程、PWM 和曲线保留，同时检查停转起步助推及过热保护。
- 原有风扇、硬件、USB WAN、设备树和 HNAT 检查继续由 `scripts/check-openfi6c.sh` 执行。

浏览器检查需 Node.js 20 或以上、Playwright 及其 Chromium。在项目测试环境可用这些依赖后执行：

```sh
node tests/openfi6c/curve.cjs
```

## 发布状态

此修复已纳入源码，当前 `v25.12-openfi6c-20260912` Release 升级包仍保留原始已验证固件。修复尚需更新设备上的插件或固件才能生效，已有固件文件及其校验和不变。

如果旧页面已经把四个 100% 保存到配置，原控制点无法从这些值推算回来，需要从备份恢复或重新设定一次。

## 2026.10.13-r1

- 起转助推后直接进入目标输出。原逻辑把 1 秒助推的 100% 当作当前输出，按每次采样最多降 10 个百分点缓降，默认约 45 秒后才到达曲线值；服务启动时同样如此。之后的正常降速仍受 10 个百分点限制。
- 等待采样时可立即响应 TERM。原脚本在前台 sleep 期间推迟处理信号，采样间隔超过 procd 的 5 秒终止超时时会被强制结束，退出前请求全速的保护不执行，风扇停留在原输出。HUP 仍在本次采样结束时应用。
- 关闭后重新开启指示灯时恢复触发器参数。内核重新选择 netdev 触发器会清空 device_name 及 link/tx/rx，internet、wifi 灯原先不再跟随 eth0、rax0；现在一并保存和恢复。
- “反转模块复位引脚”取消勾选时写入 0。原脚本只在勾选时写 1（即设备树默认值），取消勾选不起作用；GPIO 不存在时返回失败，下次启动重试。
- 移除无需登录即可访问的工厂测试页 `admin/op_help/mfg_info`。该页每次请求执行多条命令，公开 SSID、MAC、LAN IP 等信息，依赖的 `op_factory.sh` 未打包，引用的 eth1、mtd3 在 25.12 已不适用。

fan.py、hardware.py、reload.py 新增对应回归用例，旧代码均失败，修复后在 dash 和目标 busybox ash 下均通过。
